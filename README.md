# Marvel Champions Table

Table solo pour **Marvel Champions** (boîte de base, paquets de scénarios *Le Bouffon Vert*, *Les Démolisseurs* et *Kang le Conquérant*, boîte de campagne *L'Avènement de Crâne Rouge*, paquets héros *Black Widow*, *Docteur Strange*, *Captain America*, *Hulk*, *Miss Marvel*, *Thor*, *Ant-Man*, *La Guêpe*, *Vif-Argent* et *La Sorcière Rouge*, version française ; et un scénario fan-made, *Kraven le Chasseur*), en Vue 3.
Mise en place automatique, decks préconstruits officiels, import de decks par lien MarvelCDB, installable en PWA.

## Démarrer

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # tests du moteur de règles (Vitest)
npm run build        # build PWA dans dist/
npm run preview      # sert dist/ pour tester le build et le service worker
```

Node 20.19+ ou 22.12+ (exigence de Vite 8).

Le build utilise des chemins relatifs (`./`) : le contenu de `dist/` fonctionne tel quel à la racine d'un domaine comme dans n'importe quel sous-dossier. L'URL de la page doit finir par `/` (`https://exemple.fr/mc/`, pas `https://exemple.fr/mc`). Pour forcer un préfixe absolu :

```bash
BASE_PATH=/modules/marvel-champions/ npm run build
```

Référencement : `index.html` porte le titre et la description des résultats de recherche, l'adresse canonique, les balises de partage (Open Graph et X, image `public/og-image.jpg`, 1200 × 630, le logo sur la ville de nuit), des données structurées schema.org (`WebApplication`, gratuite, en français) et un texte de secours sans JavaScript (`<noscript>`). Ces balises demandent l'adresse publique complète de l'appli : `SITE_URL`, par défaut `https://www.gameboxheroes.fr/marvel-champions-table/` (`vite.config.js`, plugin `seo`, qui remplit `__SITE_URL__`, `__SITE_ORIGIN__` et `__DESCRIPTION__` ; la description sert aussi au manifeste). Le build écrit aussi `sitemap.xml` à côté de la page. Pour une autre adresse :

```bash
SITE_URL=https://exemple.fr/mc/ npm run build
```

Hors du dépôt, à faire une fois sur le serveur : un `robots.txt` à la racine du domaine (un robots.txt dans un sous-dossier n'est pas lu) avec la ligne `Sitemap: https://www.gameboxheroes.fr/marvel-champions-table/sitemap.xml` ; une seule adresse servie (http → https, www → sans www, `/marvel-champions` → `/marvel-champions/`) ; le site déclaré dans Google Search Console (et Bing Webmaster Tools), plan du site compris.

Statistiques : l'appli installée s'ouvre depuis le cache du service worker, le serveur ne voit donc presque rien passer. Elle demande elle-même `ping.txt?e=ouverture&m=appli` (ou `m=web` dans le navigateur) à chaque ouverture, et `e=retour` après plus de 30 min en arrière-plan : ce sont ces lignes qu'il faut compter dans les journaux. `ping.txt` n'est jamais mis en cache (il n'est pas dans les `globPatterns` du service worker).

Inscription aux nouvelles (« Rester informé ») : le formulaire appelle `/api/signup.php`, le script PHP du site (dossier `server/` du dépôt, installé sur le VPS d'après `server/README.md` : inscription, mail de confirmation avec lien de désinscription, mailing list ; `allowed_origins` de son `config.php` doit contenir l'adresse de l'appli). En local, `npm run dev` et `npm run preview` relaient `/api` vers le port 8000 : y lancer le script, avec PHP 8.1+ (`GAMEBOX_PRIVATE_DIR=$PWD/server/private php -S 127.0.0.1:8000 -t server/public`) ou dans Docker (`docker run --rm -p 127.0.0.1:8000:8000 -v "$PWD/server:/srv" -e GAMEBOX_PRIVATE_DIR=/srv/private php:8.3-cli php -S 0.0.0.0:8000 -t /srv/public`), avec un `config.php` de dev qui autorise `http://localhost:5173` (et le port de `preview`). Une autre adresse pour le script : `VITE_SIGNUP_URL` dans `.env` (voir `.env.example`).

`npm run build:artifact` produit `dist-artifact/page.html`, une page unique (JS et CSS inlinés, sans service worker) pour l'hébergement en artefact Claude ; les images restent à côté dans `cards/` (un dossier par boîte), `backs/` et `status/`.

Le principe : le moteur (`engine.js` et `engine/`) porte toutes les règles (mise en place, pioche, paquet Rencontre, phase du méchant, mulligan, dégâts/menace) et ne connaît que des objets JS. Le store Pinia lui passe son état réactif ; les composants ne font qu'afficher et appeler le store. Les cartes portent `data-id` et les zones `data-zone`, ce qui permet de gérer tout le pointeur à un seul endroit (`usePointer`).

### État d'une carte

```js
{ id, definitionId /* sa fiche (GUID OCTGN pour la boîte de base) */, owner /* 'player' | 'encounter' */, zone,
  side /* 0 face A | 1 face B | 2 face C (Ant-Man, La Guêpe Géant) */, faceUp, exhausted, x, y, zIndex,
  damage, threat, tokens, isIdentity?, isPawn? /* pion libre : pawn, sa sorte (PAWN_KINDS) ; color pour ceux des anciennes parties */, stunned?, confused?, tough?,
  underSchemeId? /* id de la manigance sous laquelle elle est posée, face cachée */,
  dealtToPlayer? /* carte Rencontre reçue face cachée, posée devant l'identité */,
  isBoost? /* carte de boost face cachée : retournée, elle n'entre pas en jeu */ }
```

L'ordre du tableau `cards` est l'ordre des piles : le dessus d'une pile est sa dernière carte. Les zones : `playerDeck`, `hand`, `table`, `playerDiscard`, `encounterDeck`, `encounterDiscard`, `setAside` (de côté), `invocationDeck`, `invocationDiscard`, `scenarioDeck` (deck du scénario), `outOfGame` (hors jeu). L'état complet d'une partie est décrit en tête de `src/game/engine/state.js`.

Les fiches des cartes (`src/data/*.json`) gardent des clés courtes pour rester compactes (`n` nom, `t` type, `s` set, `hp`, `bth` menace de départ, `xth` menace en plus par héros une fois révélée…) ; `data.js` les traduit une seule fois au chargement (`readDefinition`, table `SHORT_KEYS` commentée), et tout le code n'utilise que les noms lisibles (`name`, `type`, `set`, `hitPoints`, `startingThreat`…).

La partie en cours est enregistrée dans le navigateur avec un numéro de version (`savedGame.js`) : une partie enregistrée par une version précédente de la table (clés courtes) est convertie automatiquement à l'ouverture.

## Règles spéciales des héros et des scénarios (`rules.js`)

Tout ce que les cartes d'un héros ou d'un scénario demandent en plus des règles de base est réuni dans `src/game/rules.js` : une entrée par héros (`HERO_RULES`), par héros lu sur MarvelCDB (`IMPORTED_HERO_RULES`, par le set de son identité : Vision) et par scénario (`SCENARIO_RULES`), avec deux listes en clair, `automated` (ce que la table fait seule) et `byHand` (ce qui se joue à la main), et les réglages que le moteur lit :

- héros : `startsInPlay` (cartes du deck qui commencent en jeu, tous leurs exemplaires, sur la table face A avant la main de départ, par leur code MarvelCDB : Intangible de Vision, `26002` ; options face cachée et jetons de départ, `{codes: […], faceDown: true, previewFace: true}` pour les formes d'énergie de Spectrum, dont la face se voit dans l'aperçu, au survol de la souris comme au toucher qui sélectionne la carte, puisque le joueur choisit laquelle retourner, `{code, tokens: 4, tokenName: 'Pouvoir'}` pour la Force Phénix ; une fois distribuées, elles s'entourent d'un filet bleu électrique 0,6 s, effacé en 0,6 s, et la fenêtre du mulligan attend qu'il s'éteigne. Héros lus sur MarvelCDB concernés : Vision, Wolverine, X-23, Wonder Man, Jessica Jones, Shadowcat, Nick Fury, Psylocke, Phénix, Spectrum), `setupCard` (carte que la mise en place de l'identité met en main après le mulligan, le paquet mélangé ensuite : par son identifiant, le Bouclier de Captain America ; par son code MarvelCDB pour un héros importé, le Pistolet Élémentaire de Star-Lord, l'Acier Organique de Colossus ; ou par son type (et un trait), au choix du joueur, une amélioration Black Panther de T'Challa, une manigance annexe de joueur de Cable ; `fromDiscard` : cherchée aussi dans la défausse ; `intoPlay` : mise en jeu au lieu de rejoindre la main, une manigance annexe avec sa menace de départ), `heroPiles` (les piles de l'identité dans le bandeau du joueur, entre le paquet et la défausse, deux au plus, zones `heroSetAside` et `heroSetAside2` : cartes mises de côté ou decks à part ; par pile, ses cartes par leur code MarvelCDB, `{code, copies}` créant les exemplaires absents du deck, que l'import de MarvelCDB lit dans la boîte du héros comme le set Némésis, et relit au lancement si un deck sauvegardé ne les a pas ; `label`, `faceDown`, `shuffled`, `playsTop` : un clic met en jeu la carte du dessus, `returnsUnder` : une de ses cartes qui quitte le jeu retourne dessous. « De côté » de Valkyrie, Malicia et Iceberg (l'Aura de la Mort, Touché, 6 Pris Dans la Glace), « Climat » de Tornade, « Travaux » et « Dons » d'Hercule (face cachée, mélangés), « Sens » de Daredevil (face visible, mélangé ; clic droit « Voir le deck Sens ») ; les piles s'allument en bleu une fois les cartes distribuées, et « Mettre de côté » (X) range leurs cartes dans leur pile), `discardsHandAtTurnEnd` (Hulk, Enragé), `handSizeBonus` (sous forme de héros, +1 taille de main par amélioration que vous contrôlez avec un trait donné, avec un maximum : Iron Man, Tech, 7 au plus ; la fin de phase le détaille, « main de 4 en Iron Man : 1 + 3 améliorations Tech ») ;
- scénarios : `setupSteps` (cartes que la manigance 1A met en jeu), `villainHitPointsFromSchemes` (manigances annexes qui donnent des PV au méchant tant qu'elles sont en jeu : Klaw « l'Immortel », +10), `extraSets`, `setAside`, `scenarioDeck`, `oneEnvironment`, `expertSet`, `removesObligation`, `kang`, `crew`, `mainSchemes` (manigances principales : « Une fois révélée » des faces A et B, `onRevealA` / `onRevealB`, réponse forcée à chaque phase du méchant, `eachVillainPhase`, rappelés au journal) et `villainStages` (étapes du méchant : leur « Une fois révélée » quand l'étape remplace la précédente ou est posée depuis « De côté », fait par la table : `revealCardId` cherche une carte dans le paquet Rencontre et sa défausse et la révèle, manigance annexe avec sa menace de départ ou attachement avec ses jetons, puis mélange le paquet, `dealIfAlreadyInPlay` donne une carte Rencontre si elle est déjà en jeu ; `dealEncounterCards` donne des cartes Rencontre face cachée devant l'identité ; `revealScenarioDeckTop` révèle la carte du dessus du deck du scénario ; `stunHero` sonne votre héros ; sinon un texte `onRevealA`, ou `onRevealB` quand la carte est retournée, rappelé au journal).

En reprenant les cartes de chaque scénario : Klaw met maintenant en jeu la manigance annexe Réseau de Défense à la mise en place, Ultron l'environnement Drones d'Ultron ; les étapes II et III des méchants font leur « Une fois révélée » : Rhino II, Klaw II, Ultron III, Zola II et L'Homme Absorbant II révèlent leur manigance annexe (cherchée dans le paquet Rencontre et sa défausse), Crossbones II attache sa Mitrailleuse (2 jetons Munition) et Crossbones III révèle une Arme, Rhino III sonne votre héros, Taskmaster, Crâne Rouge et Le Bouffon Vert (Formule Mutagène) vous donnent leurs cartes Rencontre ; seuls Zola III (un sbire au choix) et Norman Osborn retourné (dégâts à répartir) restent rappelés au journal ; le stade 1B des Démolisseurs rappelle à chaque phase la menace sur les manigances annexes et le jeton Actif. Les capacités ordinaires des cartes (Action, Réponse, Interruption) restent à jouer à la main et ne sont pas reprises.

« Attribuez-vous une carte Rencontre » : clic droit sur le paquet Rencontre → Carte face cachée pour vous (posée devant votre identité, à révéler en la retournant) ; « Carte face cachée (boost) » la pose dans la zone Rencontre.

## Règles automatisées

- Nouvelle partie (maquette Figma « Préparation de la partie », `SetupModal`), limitée pour l'instant à la boîte de base, au paquet de scénarios Le Bouffon Vert, aux paquets héros Captain America, Hulk et Thor et au scénario fan-made Kraven le Chasseur (`AVAILABLE_PACKS` dans `data.js` : 8 héros, chacun avec son deck préconstruit, 6 scénarios dont Entreprise à Risques, Formule Mutagène et Kraven le Chasseur, 10 sets modulaires dont Savage Six ; un scénario ou un set fan-made porte un bandeau « Fan-made » au bas de son portrait, et « fan-made » s'ajoute à son nom au pied de la fenêtre ; les autres boîtes restent connues de la table pour les parties sauvegardées et les decks importés). Dans l'en-tête, trois étapes (2e version de la maquette, `SetupHex`) : le héros, le méchant et le set modulaire, vides à l'ouverture (deux crochets lavande, deux flèches vers la place à remplir) ; remplies, les crochets se resserrent en violet autour du portrait (66 px, son ombre dessous). L'étape en cours luit. À droite, la difficulté (Standard, Expert, Hasard). Dessous, les onglets des étapes (icône et nom ; flèches du clavier, Début, Fin), puis la grille de l'étape (`PortraitChoice`) : des cases de 88 px aux coins marqués, dix par rangée, deux rangées au moins, complétées de cases vides ; le portrait (78 px) est découpé dans la carte (`setup/portraits.js`). Un clic sur une case remplit son étape (le portrait se pose en 300 ms) et passe à l'étape suivante encore vide ; un clic sur une étape ou un onglet y revient. Les cases n'ont pas de légende : le pied, à gauche, montre le nom de la case survolée (ou qui a le focus au clavier), sinon l'affiche des choix (« Spider-Man vs Rhino + Alerte à la Bombe »). Le set conseillé par le méchant porte une pastille jaune. Chaque étape a sa case violette « Au hasard » : le héros (avec son deck préconstruit) et le méchant sont tirés au lancement, parmi ceux des boîtes proposées (`drawRandomHeroAndScenario`, `engine/setup.js`, appelé par le store avant de disposer la table, qui dépend du méchant), le set modulaire à la mise en place ; avec un méchant au hasard, aucun set n'est conseillé et les sets choisis sont gardés. Le héros se choisit avec son deck (maquette, 3e version) : sous les onglets, une bande sombre de bord à bord de la fenêtre porte trois sous-onglets (`DeckTabs`), soulignés d'un trait jaune qui glisse sous celui qui est choisi, et leurs trois volets défilent à l'horizontale, comme un carrousel (`HeroDecks`) ; le dernier choisi est gardé dans le navigateur (`ui.deckTab`) : la fenêtre s'ouvre dessus. « Préconstruits » : les héros proposés, chacun avec son deck préconstruit, et « Au hasard » dans la dernière case. « Mes decks » : les decks sauvegardés, en vignettes du héros (`stores/decks.js`, gardés dans le navigateur avec les fiches des cartes lues sur MarvelCDB qu'ils utilisent) ; leur croix les retire. « Charger un deck » : un lien MarvelCDB (deck publié, ou personnel si son auteur partage ses decks, `game/marvelcdb.js`) ; le chargement d'un fichier (export texte MarvelCDB `.txt`, deck OCTGN `.o8d`) n'est plus proposé, il ne marchait pas (sa lecture reste dans `engine/deckImport.js`, avec ses tests) ; dessous, la case « Ajouter ce deck à ma sélection », cochée d'avance, le garde dans Mes decks. Un deck chargé ou sauvegardé devient le choix du héros (son nom s'ajoute à l'affiche du pied) et peut jouer un héros d'une boîte non proposée. Une bande symétrique ferme la grille par le bas ; sur un écran bas (moins de 800 px), la bande est plus mince et celle du bas disparaît. Les grilles comptent leurs colonnes (`useGridColumns` : dix à la taille de la maquette, moins sur tablette) pour ne garder que deux rangées. « Lancer la partie » s'allume quand les trois étapes sont remplies. Le set modulaire et la difficulté tirés au hasard ne sont pas nommés par le journal ni par la fenêtre « Recommencer la partie » (« module tiré au hasard », « difficulté tirée au hasard ») ; une partie en expert a toutefois toujours son badge Expert dans la barre du haut. Les dos ne se choisissent plus : bleu pour les cartes du héros, violet pour les cartes de type Méchant, jaune orangé pour toutes les autres cartes Rencontre.

- Paquet vide : ni le paquet du joueur ni le paquet Rencontre ne se reconstituent tout seuls ; ils restent vides jusqu'à ce que leur défausse y soit remélangée. Piocher dans un paquet vide (bouton Piocher, clic sur le paquet, `D`, Piocher 3, main complétée en fin de phase) ou y révéler une carte Rencontre (clic sur le paquet, `E`, boost, carte pour vous) ouvre la fenêtre « Remélanger », avec la pénalité du paquet vide : une carte Rencontre face cachée, posée devant votre identité (au-dessus, là où elle se trouve ; les suivantes en éventail vers la gauche), ou un pion Accélération pour le paquet Rencontre. Une fois confirmée, la pioche ou la révélation demandée se fait (en fin de phase, les cartes qui manquent à la main). Même place pour la carte reçue au stade 3 de Kang ; un boost reste dans la zone Rencontre.
- Remélanger une défausse dans son paquet (menu de la défausse du joueur ou de la défausse Rencontre, bouton de leur fenêtre, ou d'office quand on pioche dans un paquet vide) : une fenêtre dit combien de cartes rejoignent le paquet et demande confirmation ; le paquet est ensuite mélangé. S'il était vide, la pénalité s'applique (carte Rencontre pour vous, ou pion Accélération) ; s'il avait encore des cartes, pas de pénalité. Avec Les Démolisseurs, ce sont la défausse et le paquet du méchant actif.
- Fenêtres : le fond assombrit et floute la page, sauf la carte agrandie de la colonne de droite, qui reste nette à sa place par-dessus (la fenêtre se centre à sa gauche pour ne pas la cacher) : survoler les cartes d'une pile, ou en cliquer une dans une défausse, l'y montre. Sur téléphone, la colonne de droite est sous la table : rien de tel.
- Fenêtre d'une pile (paquet du joueur ou Rencontre, défausses, « De côté », decks Invocation et du scénario) : toutes se regardent de la même façon. Les cartes y sont toutes debout (une manigance couchée tourne d'un quart de tour vers la gauche, de même sur le dessus de la pile). Un clic sélectionne la carte et l'agrandit dans la colonne de droite (sur téléphone, au-dessus des cartes) ; le clic droit ou l'appui long ouvre son menu par-dessus la fenêtre, qui reste ouverte : un appui à côté du menu, ou Échap, ne ferme que le menu, et la liste suit ce qu'on a fait. En tête du menu, l'action de la pile : Mettre en jeu (paquet Rencontre, deck du scénario, « De côté »), Remettre en jeu (défausse Rencontre), Poser sur la table (Invocation) ; puis Prendre en main, Défausser, Mettre de côté, Sur / Sous le paquet (pas pour une pioche qu'on fouille : elle est mélangée à la fermeture de sa fenêtre).
- Manigance principale achevée : quand sa menace atteint son seuil (« + » du compteur, M, menu), une fenêtre le signale et le stade suivant, mis de côté à la mise en place, la remplace à la même place, face A, avec sa propre menace de départ et son seuil (la menace en trop ne passe pas) ; son « Une fois révélée » est rappelé. Au dernier stade : défaite. Kang : le stade 3 achevé passe au stade 4 à la fin de la phase (fenêtre du méchant), ses stades 1 et 4 achevés sont des défaites.
- Héros battu : quand les PV de l'identité tombent à 0 (dégât sur l'identité, « − » du compteur), une fenêtre de fin l'annonce, « Spider-Man a été battu par Rhino. » (« battue » pour une héroïne, champ `feminine` de `HEROES`), avec Nouvelle partie / Recommencer.
- Fenêtres de changement (étape du méchant, victoire, manigance achevée, défaite, héros battu) : le changement est fait quand elles s'ouvrent ; l'« Une fois révélée » d'une nouvelle étape du méchant (Casser et Emporter révélée…) est écrit dans sa fenêtre ; « Annuler » remet la partie dans l'état d'avant l'action qui les a ouvertes (un clic de trop sur les dégâts, la menace ou la phase).
- Tours et phases : la partie commence au tour 1, en phase du héros. Le compteur de tour et les deux boutons « Phase du héros » / « Phase du méchant » (« des méchants » contre Les Démolisseurs) remplacent « Nouveau tour », « Phase du méchant » et « Révéler rencontre » ; le bouton allumé est la phase en cours.

  - On ne peut passer qu'à l'autre phase : un second clic sur la phase en cours ne fait rien. Une carte Rencontre se révèle aussi à la main (clic sur le paquet Rencontre ou `E`).

- Docteur Strange : son deck Invocation (5 cartes) est mélangé à part, face visible, avec sa propre défausse, à droite de la défausse joueur. Clic (ou `I`) : lancer l'invocation du dessus (Maîtrise des Sorts), qui part dans la défausse Invocation ; clic droit ou appui long : la lancer en la gardant (Maître des Arts Mystiques), la défausser sans la lancer (Talent Naturel, Wong), mélanger, chercher. Deck vide : sa défausse est remélangée sans pénalité. Une carte Invocation renvoyée « sur le paquet » retourne sur le deck Invocation ; glissée sur la table, elle arrive face cachée (Ouvrir la Dimension Noire).

Les effets des cartes eux-mêmes restent à appliquer à la main.

## Raccourcis

Les raccourcis de carte visent la carte sous la souris, sinon la carte sélectionnée.

Colonne de droite, jusqu'au bandeau du joueur (sur téléphone tout est sur une colonne) : en haut, les piles Rencontre, centrées et aussi serrées que celles du joueur (`--pile-gap`, 10 px ; leurs libellés rapetissent un peu sur tablette pour ne pas se toucher) ; dessous, deux onglets, Carte (la carte survolée ou touchée, en grand) et Journal. ## Tablette

Toucher une carte l'agrandit, la glisser la déplace, un double tap l'incline (ou la joue depuis la main), un appui long ouvre ses options avec la carte en grand. Sur un paquet ou une défausse, le clic droit ou l'appui long ouvre le menu de la pile : chercher dedans (paquet joueur, paquet Rencontre, deck Invocation et leurs défausses), piocher ou révéler, mélanger, reprendre la carte du dessus d'une défausse, remélanger une défausse dans son paquet. Sur un écran tactile assez large (plus de 700 px), la barre du haut est aux trois quarts de sa taille (36 px), le titre « Marvel Champions Table » encore aux trois quarts dedans, et le nom du héros remonte de 5 px au-dessus de ses PV. Une main nombreuse se resserre en éventail ; sur téléphone, elle défile en glissant horizontalement, et une carte glissée vers le haut part sur la table.

Côté code (`usePointer`) : l'appui long envoie lui-même un `contextmenu` (iOS n'en émet pas) et ignore celui d'Android ou Windows s'il arrive en plus ; le clic qui suit un geste déjà traité est absorbé (pioche en double, option du menu sous le doigt, pile découverte par une fenêtre qui se ferme) ; le double tap est détecté à la main pour le toucher et le stylet. Le navigateur ne reçoit jamais de glissement horizontal (`touch-action`), sinon il peut le transformer en « page précédente ». Les cartes jouables annulent leur `touchstart` (`GameCard`) : tout se joue en événements de pointeur, et aucun geste du navigateur ne reste en suspens quand la carte touchée quitte la page (piochée, jouée, glissée hors de la main), ce qui faisait perdre le tap suivant.

## Pistes

- Multijoueur : l'état est un objet sérialisable, il suffit de synchroniser les actions du store (WebSocket) ; le moteur reste côté client ou passe côté serveur.
- Extensions : comme pour Le Bouffon Vert, un fichier `src/data/<boîte>.json` et un dossier d'images `public/cards/<boîte>/` déclarés dans `PACKS` (`data.js`), puis compléter `HEROES` / `SCENARIOS` / `MODULAR_SETS`, et donner au héros ou au scénario son entrée dans `src/game/rules.js` (un test vérifie qu'il n'en manque aucune).
- Mode campagne de L'Avènement de Crâne Rouge (registre de campagne, améliorations, alliés Captifs gardés d'un scénario à l'autre) : les cartes sont là, la campagne n'est pas gérée. Un paquet héros ajoute son précon à `PRECON_DECKS` (`data.js`), en reprenant les cartes de la boîte de base qu'il réimprime.
- Import `.o8d` (lecture gardée dans le moteur, plus proposée dans l'interface) : il reconnaît les cartes par leur GUID OCTGN, donc seulement les héros de la boîte de base ; les cartes des autres paquets ont des id maison (`bw-…`, `gob-…`, `dem-…`).
- Import texte MarvelCDB (`.txt`, export « Text file » d'un deck ; lecture gardée dans le moteur, plus proposée dans l'interface) : les cartes y sont nommées en anglais avec leur paquet entre parenthèses (« 2x Widow's Bite (Black Widow) »). Chaque carte joueur porte donc son nom anglais (`en`, repris de MarvelCDB) et chaque boîte son nom MarvelCDB (`cdb` dans `PACKS`). Les cartes d'un paquet absent sont ignorées et listées à l'import.
- Import par lien MarvelCDB (`src/game/marvelcdb.js`) : l'API publique de [fr.marvelcdb.com](https://fr.marvelcdb.com/api/), sans compte, ouverte à toutes les origines (CORS). Un lien `…/decklist/view/N` lit une decklist publiée, `…/deck/view/N` un deck dont l'auteur partage ses decks (option de son profil), un numéro seul une decklist puis, à défaut, un deck. Les cartes sont reconnues par leur code MarvelCDB (`DEFINITION_BY_CODE` dans `data.js` : numéro de boîte `codePrefix` dans `PACKS`, puis numéro imprimé de la carte et sa face, « 08001a »). Pour un code inconnu, l'API dit si c'est une réimpression d'une carte présente (`duplicate_of_code`, par exemple Premiers Soins réimprimé dans Ant-Man). `parseMarvelCdbDeck` (moteur, sans réseau) fait la correspondance.
- Import par lien MC4DB (`src/game/mc4db.js`) : [MC4DB](https://mc4db.merlindumesnil.net), dérivé de MarvelCDB avec des héros créés par des fans, a le même format de decklists et de cartes (la reconnaissance des cartes, `readOnlineDeck` de `marvelcdb.js`, est commune). Un lien `…/decklist/view/58` (ou `/decklists/58`) se colle dans le même champ de « Charger un deck ». Son API ne se lit pas depuis le navigateur (pas de CORS) : l'appli passe par le relais du site, `/api/mc4db.php` (`server/`, partie 7 de son README ; `VITE_MC4DB_URL` pour une autre adresse), absent de la version artefact. Chaque carte absente de la table est d'abord demandée à MarvelCDB : une carte officielle y est, avec son nom français et les scans français de cgbuilder ; sinon c'est une carte de fans, lue sur MC4DB par le relais : identifiant `mc4db-<code>`, `source: 'mc4db'` (jamais cherchée chez cgbuilder, dont un code de fan pourrait désigner une carte officielle), image anglaise (MC4DB n'a plus d'images françaises) affichée par le relais (`?image=<boîte>/<code>`), qui la garde pour tous les joueurs : MC4DB refuse les rafales de demandes. Un héros de fans (Mystique, set `mystique_by_merlin`) a son alter ego, son obligation et son set Némésis comme un héros lu sur MarvelCDB ; ses règles se jouent à la main. Le service worker garde ces images (cache `mc-mc4db`).
- Cartes lues sur MarvelCDB : un héros ou une carte absents des boîtes de la table sont lus dans l'API (`marvelCdbDefinition` : nom français, type, PV, tailles de main, menace de départ et menace en plus par héros une fois révélée, Ténacité, jetons d'entrée en jeu, et l'autre face d'une carte recto verso : l'alter ego au dos de l'identité, la carte que l'API lie à une autre, ou le verso d'une carte à deux faces sous un seul code, comme Intangible / Dense de Vision, `26002`, que « retourner » fait passer d'une face à l'autre) avec l'image du site. MarvelCDB n'a qu'un scan par carte, en anglais : l'appli lui préfère le scan français de [cgbuilder](https://mc.cgbuilder.fr), `https://mc-src.cgbuilder.fr/images/carte/<dossier>/<numéro><face>.jpg` (`cgbuilderImageUrl` dans `useAssets.js` ; pour Tornade, Gambit, Wolverine, Phénix, Cyclope, Colossus, Shadowcat, Groot et Rocket Raccoon, cgbuilder inverse les faces A et B de l'identité par rapport à MarvelCDB, et `cgbuilder.json` les échange, « 1A=1B 1B=1A »), trouvé par le code de la carte à l'affichage, si bien que les decks et parties déjà sauvegardés en profitent aussi. Le numéro et la face sont ceux du code MarvelCDB (une carte recto verso sous un seul code, `26002`, a son verso rangé sous `26002b`, fichier 2B ; des variantes A, B… d'une même carte, Feux d'Artifices `47007a` et `47007b`, prennent l'image unique que cgbuilder range sous le numéro seul), pas toujours le dossier : cgbuilder numérote ses boîtes dans l'ordre des sorties françaises (MarvelCDB 02, Le Bouffon Vert, y est le dossier 3 ; MarvelCDB 03, Captain America, le 2). Et cgbuilder ne répond pas « introuvable » pour une image qu'il n'a pas : il renvoie vers un nom voisin, souvent une autre carte (1/200.jpg → 1/20.jpg), ce qu'une page ne peut pas détecter sur un autre site. `src/data/cgbuilder.json` dit donc quelles cartes il a, et où ; `python scripts/cgbuilder-images.py` le régénère en comparant, boîte par boîte, les noms des cartes des deux sites (voir l'en-tête du script). Les cartes que cgbuilder n'a pas encore (Elektra, Iron Fist en novembre 2026) gardent le scan anglais ; leurs noms (journal, menus, recherche) restent en français. Pour un héros absent, sa boîte donne aussi son obligation et son set Némésis. Les cartes ont l'id `cdb-<code>`, rejoignent `CARD_DEFINITIONS` / `DEFINITION_BY_ID` / `DEFINITION_BY_CODE` (`addImportedDefinitions`) et la partie les garde (`setup.importedDefinitions`) : rechargement et « Recommencer la partie » les retrouvent. Chaque fiche porte la version de l'import qui l'a écrite (`revision`, `IMPORT_REVISION` de `marvelcdb.js`, 2 depuis les cartes recto verso sous un seul code) : une fiche plus ancienne, gardée avec un deck ou une partie, est relue sur MarvelCDB au prochain import du deck et mise à jour sur place, pour la partie en cours comme pour les autres decks ; augmenter `IMPORT_REVISION` quand une fiche gagne une information. Le service worker garde leurs images pour jouer hors ligne. Les règles propres à ces héros que la table applique sont dans `IMPORTED_HERO_RULES` (`rules.js` : cartes qui commencent en jeu ou de côté, carte de mise en place, deck Climat de Tornade…) ; celles qui restent à faire sont listées dans `docs/heros-a-automatiser.md`, les autres se gèrent à la main. Deadpool (`regeneratesAtZero`) : sous forme de héros, tombé à 0 PV, il n'est pas battu ; ses PV reviennent à 1, il passe en alter ego et la manigance principale reçoit 1 pion Accélération, ce que la fenêtre « Pas mort ! » explique (« Annuler » revient à l'état d'avant le dégât). Magik et Faucon (`showsTopCard`) : sous forme de héros, la carte du dessus de leur pioche se montre face visible (le paquet de Magik ; le paquet Rencontre pour Faucon, pendant la phase du joueur), sans que l'état change ; glissée sur la table, elle y arrive face visible. Identités à plusieurs cartes (`identity`, assemblée à l'import avec des cartes de la boîte, et `levelUp`) : Angel a sa troisième face, Archangel ; SP//dr a Peni Parker pour alter ego et sa combinaison en jeu, qui se retourne avec l'identité ; Ironheart garde ses versions 2 et 3 dans sa pile « Versions », et « Level Up! », au menu de l'identité en héros, la remplace par la suivante. Elektra et Iron Fist sont refusés pour l'instant (`UNAVAILABLE_HEROES`) : leur deck ne se charge pas, « héros non disponible sur cette plateforme », et un deck déjà gardé n'est plus proposé dans « Mes decks ».
- Hors ligne : les images des boîtes proposées (`AVAILABLE_PACKS`) : les 209 de la boîte de base (`cards/base`, ≈16 Mo), les 57 du paquet Le Bouffon Vert (≈4 Mo), les 84 des paquets héros Captain America, Hulk et Thor (≈6 Mo) et les 32 du scénario fan-made Kraven le Chasseur (≈2,5 Mo), sont téléchargées par le service worker dès son installation, à la première visite en ligne (`globPatterns` de `vite.config.js`). Ensuite toute partie se joue hors ligne, quels que soient le héros, le méchant et le set modulaire, portraits de « Préparation de la partie » compris. Une boîte ajoutée à `AVAILABLE_PACKS` doit l'être aussi aux `globPatterns`. Les polices aussi sont dans ce cache dès l'installation : Barlow Condensed et Inter sont hébergées avec l'appli (`src/styles/fonts.css`, `src/assets/fonts`, woff2 latin et latin étendu, ≈450 Ko, licence OFL à côté), plus rien ne vient de Google Fonts ; la version artefact les embarque dans sa page. La vidéo du ciel de l'accueil (11 Mo) est demandée par morceaux par la balise `<video>`, que le cache ne garde pas : `usePreload` la télécharge une fois en entier, 20 s après l'ouverture, et le service worker la range dans `mc-intro`, d'où il la sert ensuite par morceaux (indispensable à Safari). Seul `ping.txt` reste en ligne.
- Images en tâche de fond (autres boîtes, decks importés) : à chaque nouvelle partie (et à l'ouverture d'une partie sauvegardée), `usePreload` demande toutes les images de ses cartes (recto, verso, troisième face), celles de la Rencontre d'abord, 4 à la fois quand le navigateur est inactif. Le service worker les range dans son cache (`mc-cards`, `mc-cgbuilder` et `mc-marvelcdb` pour les images des cartes lues sur MarvelCDB) : une carte révélée plus tard s'affiche aussitôt, même hors ligne. À la première visite, le préchargement attend que le service worker ait pris la main sur la page. Rien n'est préchargé quand le navigateur est en mode économie de données. À tester avec `npm run build` puis `npm run preview` : le serveur de dev n'a pas de service worker.
- Contrôle des données : comparées à l'API, les cartes saisies à la main concordent (noms, PV), sauf dix quantités du Bouffon Vert et des Démolisseurs où l'API se trompe : les positions imprimées sur les cartes (« Le Démolisseur (14/18) ») donnent raison aux fichiers du dépôt.
